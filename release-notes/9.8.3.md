# v9.8.3

Three things went wrong often enough to be worth a release: GitHub told you
"Network error" for problems that had nothing to do with your network, you had
to leave the TUI to fix a bad token, and a session file could hijack startup.
The README image viewer also gained the last two cases from the 9.8.1 notice.

## Errors now say what actually happened

A rejected token and an authenticated-but-forbidden request were both reported
as `Network error`, which named a connectivity problem you did not have. Now:

- `401` — the token was rejected: **"Bad GitHub token (401)"**
- `403` that is not the rate-limit case — e.g. SAML/SSO enforcement:
  **"Forbidden (403)"**, naming the SSO case
- `403` with `x-ratelimit-remaining: 0` — a rate limit, as before
- `5xx` and genuine connectivity failures — still a network error

A rate-limited search also used to _swallow_ the error and render as a silent,
successful "no repositories found". The real message now reaches the status
bar. For agents, the `ghfind_search_repos` MCP tool converts the error into the
structured flag it already had — `rateLimited: true` plus backoff advice —
because a tool failure reads as breakage while the flag reads as retry-later.

## Recover from errors without leaving the TUI

While the matching error is in the status bar:

| Key | Action                                                          |
| --- | --------------------------------------------------------------- |
| `t` | Inline token prompt — saves to config, re-runs the failed query |
| `u` | Clear the token and retry unauthenticated (401)                 |
| `c` | Swap in a different token (rate limit)                          |
| `r` | Retry the search or trending load                               |

`Esc` cancels the prompt. The keys are scoped to that one error — any new
search retires them, so `t` and `c` go back to cycling the theme and opening
compare. Documented in the help overlay and the README.

## A corrupted session no longer hijacks startup

A `session.json` whose query field held an MCP handshake blob (a client piped
its `initialize` request into the search box) made every launch skip the landing
menu and auto-run that garbage as a search. Two layers now:

- Startup always shows the landing menu. A saved session restores preferences
  (sort, limit, trending tab) and pre-fills the query when you pick Repo
  Search, but never runs a search on its own.
- Save and restore both go through `sanitizeSession()`. JSON-shaped or
  oversized queries are dropped; a non-restorable mode, bad sort, `NaN` limit
  or empty tab fall back to defaults. Reading from disk runs the same check as
  writing, so an existing corrupt file cannot do it again.

## Images wrapped in links render now

The common badge-and-screenshot shape — `[![alt](shot.png)](https://example.com)`
— rendered nothing at all. The markdown token walk treated any block containing
a link token as prose and discarded it, so `sst/opencode` lost the only image in
its README and `withastro/astro` lost 23 of its 25. The walk now recurses into
link tokens: the image renders, and its cells carry an OSC 8 hyperlink to the
original target, so clicking the image opens the same URL the prose version
would have.

## A README full of small images no longer floods the screen

`openclaw/openclaw` has 661 `<img>` tags in its README, 648 of them 48×48
sponsor avatars. Each rendered at 48 columns × 24 rows — a full screen per
avatar — so opening the README downloaded 649 images (1.6 MB) and produced
15,552 rows of output, in 28 seconds.

Images the README declares smaller than 100 px on any edge are now filtered
while parsing, before a single request is made. Images that declare no size
(marked `![]()` syntax) are measured from the image header after download —
`Bun.Image.metadata()` reads only the header, no pixel decode — and rejected
before rasterising. Measured on the same README:

    image urls fetched:  649 -> 1
    wall time:       28,318 ms -> ~550 ms

The trade-off is deliberate: a README that understates an image's declared size
hides that image (two of openclaw's avatars declare `width="48"` but are
420×420). The README is treated as the authority on its own layout; the
alternative — trusting the image over the README — is exactly what made these
pages unusable.

## Verification

516 tests (up from 482), plus `format:check`, `typecheck` and `lint` all green.
New tests pin the HTTP status → error mapping end to end, the session
sanitizers and the TUI startup contract, the link-recursion extraction
(including prose-links staying prose and nested links taking the innermost
href), the declared-size reader (percentages like `width="100%"` are ignored,
`px` suffixes accepted), the header-only pixel gate, and end-to-end view
behaviour: a linked-image block builds an image node instead of prose,
declared-small images make no request, and undeclared images still reach the
loader.

`README.md` Known-limitations section rewritten to match; test counts synced.
