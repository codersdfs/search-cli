# v9.11.0

Cloning stops being a command you copy.

## `ghfind clone` actually clones

The only cloning ghfind knew how to do was printing: `--pipe clone` and
`--format clone-commands` emit `git clone …` lines for you to paste somewhere
else. The new `clone` subcommand runs it.

```
ghfind clone facebook/react               # → ./react, over HTTPS
ghfind clone facebook/react --dir ~/code  # → ~/code/react
ghfind clone facebook/react --ssh         # git@github.com form
```

Three of the decisions are worth knowing about:

- **No GitHub API call.** A clone needs only owner/name, so the ref is
  validated for shape and git decides what exists and what you are allowed to
  read. Your 60/hour unauthenticated budget can never be the reason a clone
  fails.
- **The destination is `<dir>/<name>`, exactly what `git clone` would have
  made.** Existing directories are left to git's own rule — an empty one is
  reused, a non-empty one fails with git's message — rather than being
  pre-checked or replaced.
- **git's answers are passed through, not rewritten.** The CLI shows git's own
  progress and errors, and exits with git's own code (128 for a repository that
  does not exist, so a script can tell that apart from a usage error's 1). The
  single message ghfind writes itself is `git not found on PATH`, which is the
  one failure we can name with certainty.

## `Esc` → Repo → Clone

The TUI gets the same action, deliberately with a different I/O strategy: the
TUI owns the screen, so it cannot paint git's progress bar or let git stop to
ask for a password. git runs in the background with its output captured, the
full log is written to `GHFIND_LOG` when you have set it, and the status bar
shows git's own diagnosis — `✗ Clone failed: fatal: repository '…' not found`
rather than a guess about why.

`--pipe clone` is unchanged. Anything already parsing its output keeps working,
which is why the new behaviour arrived as a subcommand instead of a change to
the flag.

## Also

- `ghfind --doctor` reports whether git is on PATH. It is a **warning**, not a
  failure: only `clone` needs git, so the exit code stays 0 for anyone who
  never clones.
