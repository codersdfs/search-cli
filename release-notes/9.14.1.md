# v9.14.1

A maintenance release: no flags, keys or output change. The TUI's screen state
became a named thing instead of six copies of the same `if` block.

## One projection for the main view

The shell has always decided what is on screen from two variables: the mode
(`landing`, `search`, `trending`, `packages`) and the overlay (fifteen ids, or
`none`). Those states were real; nothing named them, and the visibility of the
five main panels was re-derived by hand in six functions.

They now live in `src/view-state.ts`:

```ts
panelsFor({ mode: "trending", overlay: "none" });
// { landing: false, search: false, toolbar: false, body: true, trendingTabs: true }
```

Three rules, written down instead of implied:

- a full-screen overlay hides every main panel;
- a floating overlay (the leader menu) leaves them visible;
- the landing menu steps aside for any overlay, and trending replaces the
  query row with its tab bar.

`applyView()` is the only writer of those five `.visible` flags. Adding an
overlay is now one id plus one projection rule, not a seventh copy — and the
matrix is testable without a terminal, which is what the 14 new tests do.

## What did not ship

The same exercise was applied to the update lifecycle and then reverted. Every
case it would have covered was either already guarded in
`markPostUpgradeSeen` or rare enough that a fix is not worth code; two genuine
but uncommon mismatches are tracked as issues #10 and #11 instead.
