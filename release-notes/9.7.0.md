# What's New in ghfind 9.7.0

CLI parity with the MCP tools — everything `ghfind mcp` exposes to coding
agents is now a first-class terminal command — plus two fixes: `ghfind mcp`
compiles again, and deep-dive shows real repo metadata.

### Added

**`ghfind deep-dive <owner/repo>`** — the MCP-only deep dive, on the CLI

- Language breakdown with percentages, top contributors, and a README
  excerpt (main → master → README.rst fallback)
- Previously the agent skill doc literally told agents to `curl` GitHub
  instead — not anymore
- `--json` exposes a structured payload (language percents, contributor
  counts, raw README) suitable for agents and scripting
- Resolves real repo metadata first: `ghfind deep-dive vercel/next.js
--json` reports actual stars, description, topics, and timestamps
- A 404 exits with `Repo not found: owner/name` instead of silently
  printing empty sections; network failures still degrade gracefully

**`ghfind --compare` export formats** — `--json`, `--csv`, `--markdown`

- Compare was text-only ("no JSON formatter for it yet"); all three
  formatters now exist, with columns matching the other export modes
- Repos that fail to resolve are reported in text output and excluded from
  the table; fewer than 2 resolvable repos exits non-zero

**Trending language filter on the CLI**

- `ghfind trending rust` — the form the README already advertised but the
  parser never handled — and `ghfind --trending rust` both work now
- `ghfind --trending --language <lang>` names the flag explicitly
- Unknown filters are rejected with the accepted list, the same validation
  the `ghfind_trending` MCP tool applies

### Changed

- The MCP server now shares its repo-ref parsing, trending-language
  validation, and deep-dive data pipeline with the CLI (new seams in
  `deepdive.ts` and `search.ts`) — one source of truth, no protocol
  behavior change

### Fixed

- **`ghfind mcp` failed to typecheck** — the id handed to
  `respond`/`respondError` stayed `JsonRpcId | undefined` because
  TypeScript's aliased-conditional narrowing does not apply through a `let`
  binding; the id is now a `const`. Runtime behavior was already correct —
  all 31 MCP tests pass unchanged.
- **Deep-dive ran on a zeroed repo stub** — stars, forks, description, and
  topics were all empty in both the CLI and the `ghfind_deep_dive` MCP
  tool; real metadata is now fetched first (see above).
