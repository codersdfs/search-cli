# v9.12.0

`ghfind pkg` stops being npm-only, and the release process gets a command.

## Five package registries behind one flag

```
ghfind pkg "terminal ui"                  # npm (the default, unchanged)
ghfind pkg clap --registry crates         # crates.io
ghfind pkg pdf --registry rubygems        # RubyGems
ghfind pkg Serilog --registry nuget       # NuGet
ghfind pkg jackson --registry maven       # Maven Central
```

Three decisions shaped the feature:

- **One query, one registry.** No cross-ecosystem merged results — that would
  force a cross-registry ranking and a flattened query grammar. `--registry`
  picks a target and the query text is forwarded verbatim to that registry's
  own search; ghfind translates nothing.
- **A download number never lies about its window.** npm reports monthly,
  crates.io a rolling 90 days, RubyGems and NuGet lifetime totals, and Maven
  Central publishes none. Every output format now labels what it prints —
  `1,234,567/mo`, `273,958,746/90d`, `729,093 total`, `n/a` — and the relevance
  score prints only where a score exists. RubyGems returns no total, so its
  `--count` is honest as `30+` instead of posing a page size as a population.
- **A registry answer ghfind cannot parse is an error, not zero results.** A 200
  whose body is a captive-portal page fails loudly with
  `<registry> search failed: unparseable response`; `--count` no longer reports
  the network's bad day as the market's quiet one.

The TUI cycles registries with `p` (or `Esc` → Search → Registry) while in
packages mode; the standalone browser takes `--registry` at launch and says so
in its header. Agents get the additive `ghfind_package_search` MCP tool —
`ghfind_npm_packages` keeps its name, schema and npm pinning, so any config
already pointing at it is unaffected.

## `ghfind release run --tag <v>`

The one command the release process was missing: it dispatches the Release
workflow — the same thing as `gh workflow run release --ref <v>`, for
maintainers who would rather type than click. `--dry-run` prints the dispatch
without sending it, and the tag must exist first; the workflow re-runs the CI
gate, builds the standalone binaries and publishes to npm exactly as before.

## Also

- `--registry` is now rejected everywhere but `ghfind pkg` (it was previously
  validated, then silently ignored: `ghfind rust --registry crates` answered
  with GitHub repositories); `--sort` is checked against the chosen registry on
  every path, including the interactive browser, and `--help` lists all seven
  strategies the parser actually takes.
- The session restores the last registry used, and a corrupted session value is
  filtered through the same whitelist as every other restored field.
