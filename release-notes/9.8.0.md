# What's New in ghfind 9.8.0

The README viewer learned to render markdown properly — and to show the
pictures inside it. Same menu item, same keys, but the overlay now shows a
repository the way its authors wrote it, images included.

### Added

**Full markdown rendering in the README viewer**

- The viewer used to approximate markdown with box-drawing text: heading
  markers became `█` prefixes, tables were hand-drawn, and everything else
  was inline-decorated plain text. It now drives OpenTUI's markdown
  renderable with a syntax style derived from your theme, so headings,
  emphasis, links, lists, blockquotes, boxed tables, and fenced code blocks
  render as markdown.
- Headings pick up the accent colour (H1 underlined), inline code the theme's
  green, links the accent with dimmed URLs — all of it follows `t` theme
  switching, and everything re-reads the palette when a README is opened.
- The document keeps its own block layout: paragraphs, lists, and code stay
  scrollable in the same overlay (`↑`/`↓`, `j`/`k`, `PgUp`/`PgDn`).

**Images now render in the terminal**

- README images — markdown `![]()` and standalone `<img>` tags — are fetched
  and drawn inline as truecolor half blocks. No image protocol support
  required: it works on any truecolor terminal, inside the normal cell
  buffer, so it scrolls and clips like every other line.
- Paths resolve the way GitHub resolves them: `docs/shot.png` and
  `/assets/banner.webp` both resolve against the branch the README came
  from, and `github.com/owner/repo/blob/<ref>/<path>` links are rewritten to
  raw content first.
- Images are cached per URL (so toggling or re-opening a README doesn't
  re-download), capped at 6 MB and 20 megapixels, and skipped entirely when
  they can't be shown usefully: SVG is vector text, badges are tiny
  machine-generated images, and neither survives rasterising. Skipped and
  failed images leave an `🖼 alt text` caption, so a README never silently
  loses a section.
- Press `i` in the viewer to toggle images off and on; the footer shows the
  current state. On a runtime without `Bun.Image` (plain Node), images
  degrade to those captions instead of erroring.

### Changed

- **The update panel's release notes render as markdown too.** The in-app
  update modal used the same text approximation as the README viewer; it now
  shares the same markdown view, so release notes show real headings, lists,
  inline code, and tables. Inline images stay off there — the panel is
  narrow and notes are prose.
- With the viewer and the update panel both migrated, the old plain-text
  markdown renderer is gone; the markdown view is the only renderer left.
- Test coverage grew with the feature: a PNG decoder (colour types, bit
  depths, `tRNS`, every scanline filter), the image-to-cells rasteriser,
  README image URL resolution and fetch behaviour, and the markdown token
  helpers — 414 tests total, no new dependencies.
