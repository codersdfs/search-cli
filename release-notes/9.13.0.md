# v9.13.0

Find the repos you did not know to search for: `ghfind similar <owner/repo>`.

## Similarity from signals GitHub already indexes

```
ghfind similar facebook/react
ghfind similar oven-sh/bun --limit 5 --json
ghfind similar rust-lang/rust --count
```

There is no embeddings service behind this and no new API. Similarity is
derived from what a repository already publishes: its topics and its primary
language. Topics are the tightest signal, so the first query is topic +
language; the next widens to the second topic, then the primary topic alone,
then language alone. Results from every query are merged, de-duplicated and
sorted by stars.

Three decisions keep the list useful rather than merely popular:

- **The source repo is always excluded**, client-side, so a repo can never be
  returned as similar to itself even when it ranks first in its own topic.
- **Forks and archived repos are filtered out** in every candidate query.
- **A star floor scales with the source** — one twentieth of its stars, never
  below one. A 2,000-star repo is compared with repos above 100 stars, not
  with everything that shares a broad topic.

A repository with no topics and no language returns nothing, and says why:
there is no honest signal to match on, and a bare popularity filter would just
print the most-starred repos on GitHub.

## The same discovery for agents

The MCP server gains `ghfind_similar_repos`. It takes `repo` plus optional
`limit` (1–100, default 10) and `token`, and returns the rendered list along
with a structured `{ repo, count, repos, queries }` payload. `queries` is the
part worth reading: it records the exact searches that produced the answer, so
an agent can explain or widen the result instead of guessing.

The CLI formats match the rest of ghfind — `--json`, `--csv`, `--markdown`
and `--count` — and `--limit` defaults to 10 for this command rather than the
global 50, because a similarity list stops being scannable well before that.
`ghfind similar` is also in the bash/zsh/fish completions and the bundled
agent skill.

## Fixed before it shipped

- Multi-word language names (`Jupyter Notebook`, `Visual Basic .NET`) were
  split into a language qualifier plus a stray keyword when the planned query
  was re-parsed. They are quoted now.
- An empty result for a repo that _did_ have topics used to claim the repo had
  neither topics nor language. That explanation now appears only when there
  was nothing to match on.
