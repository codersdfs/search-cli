# v9.10.1

A bug-fix release, found by crawling the whole source against its own docs.
Three of the eight issues were the kind that quietly cost you time: a flag
that was documented everywhere but never parsed, a typo that opened a GitHub
issue tab instead of printing an error, and an empty query that came back as
a network problem you didn't have.

## `--interval` was never parsed

`--interval` appeared in `--help`, the README, the how-to guide and all
three shell completions. `parseArgs` had no case for it. So
`ghfind --watch --interval 60` searched for the literal string
`"--interval 60"` and polled at the default 300s anyway. It now parses a
positive whole number of seconds — and rejects anything else with a message
instead of a mangled query.

## A typo used to open a GitHub issue tab

`--format jsonn` threw `Unknown format` from inside the run, which the top
level error handler classified as unexpected: it printed "ghfind encountered
an unexpected error" and opened a prefilled GitHub issue page in your
browser. `--pipe clonee` was the opposite failure — it did nothing at all
and exited 0.

Both flags now validate up front, print the list of valid values, and exit 1
before any search happens.

## An empty query was a network error

`ghfind --count` with no query sent `q=" "` to GitHub, got a 422 back, and
surfaced it as `⚠ Network error — check your connection. Retrying in 5s...`
— a connectivity problem you didn't have, on a loop. The search, format,
pipe and watch handlers now fail fast with a usage hint instead.

## The rest

- **Bare `ghfind --trending` opens the trending view.** It used to fall
  through to the landing menu, contradicting TRACKER.md.
- **`--since` validates its value** (`daily|weekly|monthly`) instead of
  silently falling back to daily — the same treatment `--sort` already had.
- **Watch mode honors `--since`.** The trending period was derived from the
  query string, so `--watch --trending --since weekly` polled daily. An
  explicit `--since` wins; the query-string convention still works when the
  flag is absent.
- **The MCP `ghfind_user_profile` tool returns formatted text**, matching
  `ghfind_org_profile` and the CLI's default `ghfind user` output — the raw
  JSON still rides along in `data`.
- **The trending footer matches its `/` key** (`/ top` — it scrolls to the
  top, it never opened search), and the quit paths of the main TUI, trending
  and package browser now call `renderer.destroy()` before exiting, so the
  terminal is released properly.

## Removed

Dead code with no importers: `src/search-state.ts` (still referenced the
pre-unification `config.githubTokens`), `src/export.ts` and `src/pipe.ts`
(byte-for-byte duplicates of `src/output.ts`, which is what everything
imports), and the unused `historyCount()` export.
