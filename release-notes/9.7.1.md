# What's New in ghfind 9.7.1

The in-app update finally works — plus a Windows URL fix and a new doctor
check that names every stale install shadowing your updates.

### Fixed

**In-app update installed to the wrong location**

- When the TUI runs under Bun, `performUpdate()` ran `bun install -g
github-search-cli`, which targets Bun's own global dir (`~/.bun`) — not
  the npm prefix where the running copy and its `ghfind` shim live. The
  command exited 0, "update succeeded", and the running install never
  changed.
- The updater now detects which package manager owns the running tree
  (`detectInstallLocation`: npm global prefix vs `~/.bun` global) and
  installs with `npm install -g --prefix <prefix>` for npm-owned installs,
  so the update lands exactly where the running install is.
- Compiled binaries and dev checkouts (no `node_modules` ancestor) refuse
  self-update honestly instead of npm-installing a copy you aren't running.

**Node fallback couldn't launch npm on Windows**

- `child_process.spawn` without a shell cannot execute `npm.cmd` — recent
  Node rejects it outright with `EINVAL`. The update spawn now goes through
  `node:child_process` on every runtime with `shell: true` on win32, so the
  Node fallback path works on Windows too.

**Windows: URLs truncated at the first `&`**

- Opening URLs via `cmd /c start "" <url>` split the URL at the first
  unquoted `&` — a query-string separator — and tried to execute the rest
  as a command. Every pre-filled crash-report/issue link lost its body and
  labels.
- Both URL openers now use `explorer.exe` on Windows, which receives the
  URL as a single argument, so `&` is never interpreted.

**New `ghfind --doctor` check: stale/PATH-shadowing installs**

- Multiple `ghfind` copies on PATH resolving to different versions are the
  classic "updater said OK but nothing changed" trap: the update lands in
  one prefix while the shell keeps launching another. `ghfind --doctor` now
  lists every install with its version and prints the exact
  `npm uninstall -g github-search-cli --prefix <dir>` command to remove the
  stale ones.

### Changed

- **CI enforces lint + typecheck** — the repo's first green Biome baseline
  (198 diagnostics triaged, real `@biomejs/biome` 2.5.14 dependency replacing
  the phantom `biome@2.5.13` pin) and a `.gitattributes` forcing LF so
  `prettier --check` passes on Windows runners (main had been red on
  windows-latest for weeks). Previously both gates were excluded as
  known-broken; the typecheck-opentui-drift ticket is closed.

### Internal

- `open-url.ts` is runtime-agnostic with a detached Node fallback (it
  previously crashed under Node via unconditional `Bun.spawn`).
- Housekeeping: `mcp-server.ts` assignment-in-expressions, `trending-parser.ts`
  stateful regex loop → `matchAll`, typed casts replacing `as any`, and a
  repaired unsafe-autofix regression in `TrendingAdapter`.
